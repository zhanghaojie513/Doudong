# Skill 自动进化（dougong.skills.evo）设计笔记

> **状态**：候选设计，2026-10-23 技术评审修订；尚未实现或验证效果。
> **落点**：M2 做最简 L1 候选生成、受限启用与退化检查；M3 后逐步建设官方可选插件 `dougong.skills.evo` 的 L1–L3 能力。
> **参照**：[Hermes Agent](https://github.com/NousResearch/hermes-agent) 的经验沉淀思路；具体机制与格式在实施时核实版本，不推定已与其行为等价。
> **设计边界**：插件提供加载、复盘和评测能力；Memory/Skill 是有来源、作用域与版本的内容。个人适配是待验证目标，不承诺任务越多必然越好。

---

## 1. 是什么

任务完成记录提交 → 按策略选择材料并复盘 → 生成候选 Memory/Skill → 检查、评测与审批 → 启用指定版本 → 后续运行按需加载 → 观察效果并允许撤销。

“生成”“启用”“加载”和“执行”是不同动作。模型生成的内容、工具输出、仓库文件都可能含错误或提示注入；复盘不能把这些材料当作更高优先级指令，也不能从用户一次允许/拒绝推导永久授权。进化内容不得覆盖系统指令、审批策略或工作区边界。

## 2. 架构映射与待验证前提

| 环节 | 拟复用组件 | 必须补齐的契约 |
|---|---|---|
| 复盘原料 | 已提交会话日志与执行记录 | 定义 task/turn/call ID、用户纠正、审批决定、工具终态及来源关联；日志不预设包含完整编辑证据 |
| 触发 | 已提交的任务完成记录 + 事件通知 | 不能把进程退出或裸 SessionEnd 等同任务成功；通知仅唤醒，扫描提交记录补齐漏通知 |
| 复盘调度 | 官方可选插件 | 持久化处理游标、任务状态与幂等产物 ID；中断后可续处理，不重复启用 |
| 模型调用 | Ai 工厂及指定 provider | 独立配置模型处理位置、材料范围、预算、脱敏和外发策略 |
| 产物存储 | 版本化 Memory/Skill 存储 | 候选/启用状态分离，内容哈希、作用域、来源、评测、审批、撤销记录可追溯 |
| 加载和执行 | 加载器 + 同一工具 dispatcher | 记忆注入有大小/数量限制，技能按需查询；脚本执行不绕过参数校验和权限审批 |

这与插件架构兼容，但不是“零新增采集”。必须先证明现有持久化 schema 足够，缺少证据时明确标为未知，不能由模型补造。记录采用最小必要字段，秘密、凭据和隐私原文不得为复盘无条件保留。

最小产物元数据包括 `artifactId/version/contentHash`、类型、候选/启用/撤销状态、用户与工作区作用域、来源任务/记录区间、生成模型配置标识、创建时间、有效期、评测结果、审批标识及替代版本。稳定偏好与临时任务要求分开；冲突、重复和过期内容先合并/提名，不无限叠加 prompt。

## 3. 分层风险模型

| 层 | 内容 | 生效方式与约束 |
|---|---|---|
| L1 偏好记忆 | 语言、输出格式、命名等结构化低风险偏好 | 默认生成候选；只有用户预先启用受限自动记忆策略后，白名单字段才可自动启用，保留来源、作用域、有效期与撤销入口 |
| L2 行为规则 | 工具使用、任务流程等规则 | 默认待审，明确差异与评测结果，批准指定内容版本后启用；不生成授权规则 |
| L3 技能内容 | SKILL.md、相关说明与脚本 | 审批绑定不可变版本及内容哈希，加载前复核；更改后重新审核。批准技能不等于批准其中任意命令 |
| L4 权限配置 | 审批策略、allowlist、provider 外发策略等 | 禁止由进化产物自动更改，经宿主专用人工授权路径管理 |

L1 会持久影响后续行为，不是零副作用。一次命令拒绝可能只是针对当前参数、时间或工作区；任何级别都不得从审批历史自动推广权限。只有非权限类偏好可进入受限 L1 白名单，跨工作区默认不传播，明确用户级偏好才可共享。

权限配置不通过普通技能存储写接口暴露给进化插件。常规文件工具对配置路径作保护，shell 保持明确审批；可信进程内插件和广权限 shell 仍可能直接改文件，因此“禁止自动放权”是受支持执行路径的契约，不是对同权限恶意代码的隔离保证。

## 4. 成本、隐私与防退化

1. **成本**：按任务/会话/汇总配置复盘频率、token/时间/费用上限，失败有限重试；没有有效材料可跳过。模型选择以任务需要和数据策略为准。缓存效果依赖 provider，不承诺命中或固定节省比例。
2. **隐私**：本地存储与模型处理位置分别声明。复盘材料发给远端模型、以及启用记忆注入远端 prompt，都是外发；两条数据流分别配置允许的 provider、脱敏、用户选择和作用域。只有全部相关推理在本地且禁止外发时才能承诺“不上传”。
3. **最小退化检查**：M2 启用自动记忆前即保留无记忆基线、独立留出任务与负面样例，按项目/会话划分生成和评测材料。验证任务成功率、偏好遵循、权限违规、隐私泄漏及成本；命中率或纠正减少本身不足以证明改进。完整评测搜索平台可以后置，最小对照不能后置。
4. **回滚**：恢复产物启用指针与版本，并清除加载缓存；新 turn 使用新快照。运行中 turn 固定记录原内容版本，撤销后先暂停，在下一模型请求前重建上下文；已经发送给模型的内容无法撤回，必要时新建会话。回滚不能撤销已发生的外部副作用。
5. **删除与审计**：append-only 适合记录版本变更，不代表敏感材料永远不可删。支持清除产物、派生摘要、索引和受控备份中的相关内容，保留不含敏感正文的撤销/删除审计；无法清除的外部 provider 历史明确告知。规则审计可提名过期或冲突项，不能凭高命中率自动放宽权限。

## 5. 与插件理念的关系

**插件承载能力，技能提供内容。** 加载器、复盘器和评测器由内核管理；技能文件不能直接注册 .NET 服务或在进程内注入代码。插件也可携带有版本的技能内容，但启用和加载仍遵守同一规则。

- 技能脚本通过已注册工具及统一 `IToolDispatcher` 执行；文件读取、脚本运行、联网等分别接受权限校验，不限定必须由 bash 实现，也不建立第二执行通道。
- 技能内容可以免编译更新，但候选检查、审核、启用与内容完整性校验完成后才生效。代码插件仍需构建、兼容和生命周期验证。
- 偏好记忆按受限预算注入；Skill 目录先只提供名称、说明和版本，由模型按需加载允许的内容，避免全量注入。加载结果同样是不可信资料，不能覆盖上层指令。
- 成熟重复能力可提议实现为插件；该过程仍需人工开发和测试，不由进化插件自动加载生成程序集。
- dsh 的技能承载可作实现参照；具体包名、格式和版本需在实施时核实，本项目不以第三方功能对照证明自身已实现。

## 6. 与 MAF Skills 的关系

官方 Harness 文档提供 Skills 和上下文扩展能力，可作为加载格式与集成候选。能否支持本项目的动态内容更新、来源审计、审批版本和撤销，需要结合 [design.md §2.1](design.md#21-基础件与-maf-复用决策2026-10-23-修订) 的固定版本 PoC 验证。

不把“静态加载”“企业/个人分水岭”或“缺少进化闭环”作为未经核实的绝对比较。Dougong 的目标是形成可观测、可撤销的个人适配流程，选择 MAF 或自研加载器都须遵守相同信任与执行契约。

## 7. 里程碑与验收

- **M2**：最简 L1，包含已提交任务记录触发、持久化处理游标、候选存储、受限启用、来源/作用域/撤销与最小留出评测。默认候选待确认，自动启用仅限用户选择的白名单策略。
- **M3 后**：逐步建设官方可选插件 `dougong.skills.evo` 的 L1–L3 审查、版本、按需加载和审计。尚未验证，不按“完整实现”作工期承诺。
- **M4+ 可选参考**：[Hermes 离线进化项目](https://github.com/NousResearch/hermes-agent-self-evolution) 的评测驱动优化思路；采用前核实源码、数据要求与版本。不把既有会话同时作为生成材料和唯一评测集。

验收至少包括：

1. 同一固定模型/配置下，记忆启用前后在独立留出任务上对比；预先记录样本、指标和容许退化范围，无未解释的安全/隐私违规。结论仅适用于被测条件，不保证第 N+1 次必然不再纠正。
2. 注入带恶意指令的工具结果，不能转成权限、跨项目规则或更高优先级指令；一次审批不能自动演变成 allowlist。
3. 在本地可用、无外部模型等待的测试环境，单条产物撤销后 30 秒内影响新 turn，其他产物保持原版本；活动 turn 暂停/重建行为与 §4 一致，不宣称撤销外部副作用。
4. 未审批、审批后被篡改、过期或已撤销的 L3 内容不得加载；已批准技能中的脚本仍须逐调用通过工具权限管线。
5. 复盘过程中退出、重复完成通知或模型调用失败，不重复启用产物；日志材料不全时产物标记证据不足。
6. 远端复盘与记忆注入的数据流分别可观察、可禁用，清除能覆盖受控派生产物；用户能查看当前启用内容、来源、版本及作用域。
